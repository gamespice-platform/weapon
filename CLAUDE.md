# GameSpice Weapon

What a player holds and uses. A weapon is a document (`GSWeaponDef`) that names a behaviour script by path; the arsenal runs slots, cadence, ammunition and reloads, and the behaviour decides what a use does, returning shots for gs-combat and spawns for the game.

Read the family [CLAUDE.md](../../CLAUDE.md) first.

**The distributable is `addons/gs_weapon/`.** It requires [GameSpice Core](../gs-core) and [GameSpice Combat](../gs-combat) (symlinked into `addons/`, gitignored). gs-net, gs-loadout, gs-inventory and gs-player are optional and never named.

Also requires **GameSpice Profile** (`GSProfileSet`, `GSProfile`, `GSProfileRuntime`, split from GameSpice Core): link `addons/gs_profile` next to `addons/gs_core`.

## Running and testing

The family's two steps ([family CLAUDE.md](../../CLAUDE.md#validating-anything)), then `timeout 180 godot --headless --path . res://examples/weapon_selftest.tscn` and `res://examples/spawner_selftest.tscn`.

## Rules that bite

- Adding a weapon edits nothing here: a script extending `GSWeaponBehaviour`, a `GSWeaponDef` naming it by path, a catalogue row. [design](docs/design.md#the-one-idea)
- A behaviour is a pure function of the context: no clock, node, input device or random stream. [design](docs/design.md#four-rules-for-a-behaviour-and-they-all-break-quietly)
- A behaviour applies nothing; it returns a `GSWeaponOutcome`. [design](docs/design.md#four-rules-for-a-behaviour-and-they-all-break-quietly)
- Behaviour state lives in `state`, never a member, or a correction loses it. [design](docs/design.md#four-rules-for-a-behaviour-and-they-all-break-quietly)
- Check `ctx.replayed` before any sound, effect or statistic. [design](docs/design.md#four-rules-for-a-behaviour-and-they-all-break-quietly)
- Every duration on a definition is in ticks, at `authored_tick_rate` when set (0 = the running rate, unscaled); the arsenal reads them only through `ticks_for`/`charge_for`, a behaviour through `scaled_ticks`/`scaled_per_tick`. [design](docs/design.md#ticks-never-seconds)
- `GSWeaponOutcome.cooldown_ticks` is in the definition's ticks (the arsenal scales it); a `GSWeaponSpawn`'s fuse and life are in running ticks (the behaviour scales them). [design](docs/design.md#ticks-never-seconds)
- Client and server arsenals must share `tick_rate`; deadlines are absolute ticks in the snapshot. [design](docs/design.md#ticks-never-seconds)
- In `_try_use`, ask whether the weapon can pay before cancelling a reload. [design](docs/design.md#the-order-in-_try_use-is-load-bearing)
- `select()` refuses the slot a switch is already heading to; a game may send its slot every tick. [design](docs/design.md#select-refuses-the-slot-a-switch-is-already-heading-to)
- `GSSpread` stays in GameSpice Combat; behaviours set `GSShot.spread`. [design](docs/design.md#spread-lives-in-gs-combat-not-here)
- Never name a class from GameSpice Net, GameSpice Loadout, GameSpice Inventory or GameSpice Player: duck-type it (a writer is `Variant`), or the script fails to parse where that addon is absent. [design](docs/design.md#optional-neighbours-are-duck-typed)
- `GSWeaponCatalogue.ids()` and `GSWeaponAmmo.pools()` are in text order: sort StringNames with `String(a) < String(b)`, never `sort()` (interning order, differs per process). The suite's id-order section is armed against it. [gdscript-hazards](../../docs/gdscript-hazards.md)
- Attachments apply to a deep copy of the definition, never the catalogue's row, and that copy is memoed and shared by every holder of the same fitting: never edit a fitted def, and `touch()` a base def edited in place; both machines must share the attachment catalogue (the wire carries indices into it). [design](docs/design.md#attachments)
- The suite's extension-point section (`fixtures/lightning_rod.gd`) must keep passing. [design](docs/design.md#the-extension-point-is-tested)

## Consumers

game-fatal-contact and game-airdrift use it directly. game-playlot, game-zombie-zone, mg-deathrun, mg-prop-hunt, mg-smash-copter and mg-wipeout use it through zee-gs-weapons. game-playlot's prop tools (`GSPropTool` subclasses) are not weapons in this sense.
